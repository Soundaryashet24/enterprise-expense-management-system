# enterprise-expense-management-system
A backend application for managing employee expenses, approvals, reimbursements, and expense workflows using Java and Spring Boot.

### Architecture

Client ->  REST Controller ->  Request / Response DTO ->  Service -> Repository -> MySQL

   
### Request Validation and Error Handling Flow

The Employee API uses Jakarta Bean Validation to validate incoming request data before it reaches the service layer.

**Validation rules**
- Employee name is required and cannot contain only whitespace.
- Employee name cannot exceed 100 characters.
- Employee email is required and must follow a valid email format.
- Employee email cannot exceed 150 characters.

**Error handling**

Controller -> Service -> EmployeeNotFoundException -> GlobalExceptionHandler -> HTTP 404 NOT FOUND

Invalid request data returns `400 Bad Request` with field-level validation messages. Requests that reference a non-existent employee return `404 Not Found`, provided the global exception handler is configured.

**Example invalid request**

```json
{
  "name": "",
  "email": "invalid-email"
}
```

**Example error response**

```json
{
  "name": "Employee name is required",
  "email": "Please provide a valid email address"
}
```

Validation is applied to employee creation and update requests using `@Valid` on the request DTO.

              
## Employee API Reference

Base URL: `http://localhost:8080`

| Method | Endpoint | Description | Success status |
|---|---|---|---|
| GET | `/employees` | Retrieve all employees | `200 OK` |
| GET | `/employees/{id}` | Retrieve an employee by ID | `200 OK` |
| POST | `/employees` | Create an employee | `201 Created` |
| PUT | `/employees/{id}` | Update an employee | `200 OK` |
| DELETE | `/employees/{id}` | Delete an employee | `204 No Content` |

### Request Example

Create an employee using `POST /employees`:

```json
{
  "name": "Anita",
  "email": "anita@example.com"
}
```

The employee ID is generated by the persistence layer and returned in the response. A successful creation also includes a `Location` header identifying the new employee resource.

### Error Responses

- `400 Bad Request` — invalid request data, including failed DTO validation.
- `404 Not Found` — the requested employee does not exist.

Error responses are handled through the application's centralized exception handling.

### API Design

The Employee API uses request and response DTOs to separate API data from the JPA entity. The controller delegates operations to the service layer, which uses the repository to interact with the database.
